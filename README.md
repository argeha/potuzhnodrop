# ПОТУЖНО DROP 5.8

Гра-пародія на сайти з апгрейдом CS2. Не приймає гроші або предмети, не створює Steam Trade Offers та не видає реальних призів.

## Cloudflare Workers

Проєкт працює у вже створеному Cloudflare Worker `potuzhnodrop`. Статичний сайт, API, профілі, перевірювані ролли та чесна 1v1-черга розгортаються одним Worker'ом; стан зберігається у SQLite-backed Durable Object, доступному на безкоштовному плані Cloudflare. Перед deploy `npm run build` збирає локальний Tailwind і створює чисту папку `dist/` лише з публічними файлами.

Для локальної перевірки:

```bash
npm install
npm run build
npm run dev
```

Git-збірка Cloudflare має виконувати `npm run build`; після цього Wrangler зчитає `wrangler.jsonc` і розгорне Worker з `dist/` у наявний сервіс.

## Перед великим запуском

Для production обов’язково створи секрети **в Cloudflare**, а не у файлах репозиторію:

```bash
npx wrangler secret put FAIR_SEED_SECRET
npx wrangler secret put STEAM_WEB_API_KEY
npx wrangler secret put ADMIN_OWNER_PASSWORD
```

- `FAIR_SEED_SECRET` — випадковий рядок від 32 символів. Він дозволяє безпечно обчислювати однаковий щоденний seed у багатьох Worker-шардах і не робити один сервер точкою затору. Встановлюй його перед новою UTC-добою, щоб не змішувати старі й нові proof одного дня.
- `STEAM_WEB_API_KEY` — серверний ключ Steam Web API. З ним Worker бере нік і аватар через офіційний `GetPlayerSummaries`; ключ ніколи не надсилається у браузер. Без нього залишається безпечний запасний режим через публічний профіль Steam.
- `ADMIN_OWNER_PASSWORD` — окремий пароль власника для адмін-панелі, щонайменше 24 символи. Він перевіряється тільки Worker'ом і ніколи не надсилається назад у браузер або GitHub. Згенеруй його в менеджері паролів; не використовуй пароль від пошти чи Cloudflare.

Не публікуй значення цих секретів у GitHub, Telegram, скріншотах чи frontend-коді. Перед масовим анонсом перевір production-домен у чистому браузері: Steam-вхід, повторне завантаження, аватар, публічний/закритий інвентар та відключення сесії.

## Адмін-панель і ролі

Панель відкривається за адресою `/admin`. Її API живе окремо від ігрового API, а ролі, сесії та аудит зберігаються у серверному Durable Object. Браузер не може сам призначити собі роль: кожну дію ще раз перевіряє Worker.

- **Власник** — входить через `ADMIN_OWNER_PASSWORD`; захищений від будь-якої зміни в панелі.
- **Повний адмін** — може керувати всіма нижчими ролями, але не власником і не іншими повними адмінами. Також має повне керування віртуальними серверними профілями.
- **Адмін** — може додавати й змінювати модераторів та підтримку; у грі може лише видавати віртуальні нагороди, без скидання чи вилучення даних.
- **Модератор** і **підтримка** — не можуть видавати доступи.

Після входу власник створює учасника, обирає роль і отримує разове посилання. Воно діє 24 години, після першої активації зникає з сервера, а доступ зберігається в `HttpOnly`, `Secure`, `SameSite=Strict` cookie на 14 днів. Призупинення або видалення учасника одразу відкликає всі його активні сесії. Cloudflare Zero Trust, платіжна картка й сторонній логін для цього варіанта не потрібні.

Розділ **«Керування профілем»** працює лише з Cloud Profile: у профілі гравець відкриває вікно відновлення та передає адміну свій `Cloud Profile ID` (не код відновлення). Там можна видати або встановити віртуальні PC, XP, квитки, Battle Pass, престиж і скіни з серверного каталогу; повний адмін також бачить та може прибрати скіни. Зміна збільшує серверну версію профілю, тому відкритий на іншому пристрої клієнт мусить спершу завантажити актуальний прогрес, а не перезаписати його застарілою копією. Усі дії потрапляють до журналу.

## Що нового в 5.8

- Кожен кейс має власний тематичний склад: ножові — лише ножі, рукавичкові — лише рукавиці, AWP/AK/M4 — лише відповідну зброю. Загальні дешеві предмети більше не змішують усі кейси між собою.
- Віртуальні PC-діапазони та відкриті шанси сформовані всередині кожного пулу: є звичайні невигідні дропи, окуп, рідкісні прибуткові предмети й дуже рідкісні топ-дропи.
- Рулетка більше не виділяє майбутній виграш. Вона завершується разом із треком прокрутки, а предмети в стрічці відображаються за тими самими шансами, що й реальний результат.
- Кейсова стрічка та монетка в «Потужному бою» знову працюють через перевірену CSS-анімацію й не вимикаються системним режимом зменшеного руху. Результат з’являється лише після завершення руху.
- Картинки скінів у кейсах та Live Skins беруться з реального каталогу; резервне зображення використовується тільки якщо мережеве зображення справді не завантажилося.
- Live Skins одразу показує власні перемоги з апгрейдера, кейсів, «Потужного бою» та Jackpot Royale.

- API більше не завжди проходить через один глобальний Durable Object: нові серверні профілі, публічні профілі та Steam-сесії автоматично розподіляються за окремими shard-ами. Наявні профілі безпечно переносяться під час першого звернення з правильним кодом відновлення.
- Хмарний профіль має монотонну `revision`: застаріле збереження з другої вкладки або іншого пристрою відхиляється замість того, щоб безшумно перетерти новіший прогрес.
- Додано edge rate limit для профілів, Steam, інвентарю, fair-roll, 1v1 та каталогу. Надмірні запити отримують `429` і `Retry-After`, не створюючи нескінченне навантаження на Worker.
- Усі POST-запити API відхиляються, якщо браузер надсилає чужий `Origin`.
- Нові Steam-сесії ізольовані від глобального стану. Це знімає найбільш важке навантаження — аватари, профілі та синхронізацію інвентарю — з черги ігрових режимів.
- Каталог CS2 кешується у виділеному Worker-shard на 6 годин і може віддати останню валідну копію до 7 днів, якщо зовнішнє джерело тимчасово недоступне.
- Закриті 1v1-кімнати ізольовані одна від одної; загальна швидка черга зберігає один пул, щоб реальні гравці могли знаходити суперника.
- Додана підтримка офіційного Steam Web API для стабільних аватарів і нікнеймів із контрольованим fallback, якщо Steam тимчасово недоступний.

- Вхід використовує офіційний Steam OpenID із одноразовим state, який зберігається в `HttpOnly` cookie та завершується через 10 хвилин.

- У профілі можна повторно увійти після завершення сесії або відключити Steam від цього браузера. Відключення не торкається Steam-акаунта і не видаляє віртуальний ігровий прогрес.

## Що нового в 3.9

### ☁️ Серверний профіль без сторонньої бази

- У профілі з’явилась ручна серверна синхронізація: створення, збереження і відновлення віртуального прогресу.
- Профіль захищений випадковим кодом відновлення. Сервер зберігає лише його SHA-256 hash; сам код показується тільки гравцеві.
- Можна підключити наявний профіль на іншому пристрої через ID та код. Файл експорту більше не містить цього секрету.
- Зміни обробляє один Durable Object, тому збереження та матчмейкінг не мають гонок запису.

### 🎲 Перевірювані кейси

- Для кожного відкриття сервер створює HMAC-SHA-256 результат із приватного денного seed, власного client seed, ID пристрою, nonce та ID кейсу.
- До розкриття seed показується його hash; наступного дня в профілі можна перевірити hash і обидва числа раунду — вибір скіна та знос.
- Повторний запит із тим самим nonce та параметрами повертає той самий результат; спроба використати nonce для іншого раунду відхиляється. У production недоступний серверний рол скасовує відкриття та повертає баланс. Лише локальна розробка може використати явно неперевірюваний fallback.
- Усе це перевіряє лише віртуальні дропи і PC-значення гри; реальних скінів, грошей або виведення тут немає.

### 🛡 Стабільність раундів і безпечні дані

- Ставка в бою одразу резервується: її не можна продати або використати в іншому режимі до результату.
- Перезавантаження під час апгрейду, бою або Royale скасовує незавершений раунд і повертає ставку.
- Royale не скидає учасників під час анімації, навіть якщо відкрити іншу сторінку.
- Каталог скінів проходить валідацію, а дані з імпорту очищуються перед відображенням.

### 🎲 Чесніші кейси

- Пули кейсів мають доступні предмети, тому ножі й рукавиці більше не випадають майже в кожному відкритті.
- Шанс розподілений за ціновими рівнями: більшість дропів нижчі за ціну кейса, а дорогі — справді рідкісні.
- Безкоштовний кейс має 75% бюджетних, 22% середніх та 3% вищих дропів.

### 🎨 PNG-кейси та SVG fallback
Кожен із 14 кейсів має власну оптимізовану PNG-ілюстрацію. Якщо локальний файл недоступний, сайт використовує вбудований SVG fallback із градієнтом, світінням і замком.

- **Сірий** — базові скіни, 100 PC
- **Синій** — Restricted, 300 PC
- **Фіолетовий** — Classified, 1 000 PC
- **Золотий** — Covert / Ножі, 5 000 PC

PNG-файли не потребують CDN і кешуються браузером; SVG fallback не робить зовнішніх запитів.

### 🔧 Фікс Battle Royale
Був неприємний баг: коли гравець перемагав у Royale, його власний предмет **усе одно видалявся** з інвентарю. Тепер логіка правильна:

- 🏆 **Перемога** — свій предмет **залишається** + забираєш 3 предмети ботів
- 💀 **Програш** — свій предмет **видаляється** (переходить переможцю)
