# ПОТУЖНО DROP 7.5.2

## Що нового в 7.5.2

- Вітрина профілю стала свідомим вибором: гравець сам обирає рівно до трьох
  скінів з інвентарю, а порожні слоти ведуть у зрозумілий менеджер вітрини.
- Кожен кейс отримав паспорт із п’яти незмінних предметів із його власного
  каталогу. Прогрес визначається лише фактичними скінами в інвентарі;
  завершення дає один профільний трофей і +120 XP, але ніколи не видає PC.
- У каталозі кейсів з’явилася вкладка «Колекції кейсів» з загальним лічильником
  трофеїв та прогресом по кожному кейсу. Паспорти не впливають на RTP, шанси
  або ціни дропів.

## Що нового в 7.5.1

- Верхній подарунок відкриває чесний семиденний календар: невеликі щоденні
  віртуальні PC, скидання серії після пропуску та один прив'язаний
  колекційний скін на 7-й день. Він не продається, не потрапляє в апгрейдер і
  не змінює шанси.
- У профілі з'явилися п'ять стилів оформлення, що відкриваються лише звичайним
  прогресом у грі. Це косметика інтерфейсу, а не джерело PC чи переваги в
  режимах.

## Cloudflare Workers

Проєкт працює у вже створеному Cloudflare Worker `potuzhnodrop`. Статичний сайт, API, профілі, перевірювані ролли та чесна 1v1-черга розгортаються одним Worker'ом; стан зберігається у SQLite-backed Durable Object, доступному на безкоштовному плані Cloudflare. Перед deploy `npm run build` збирає локальний Tailwind і створює чисту папку `dist/` лише з публічними файлами.

Для локальної перевірки:

```bash
npm install
npm run build
npm run dev
```

Git-збірка Cloudflare має виконувати `npm run build`; після цього Wrangler зчитає `wrangler.jsonc` і розгорне Worker з `dist/` у наявний сервіс.

## Android / Google Play

У репозиторії є Capacitor-проєкт `android/`. Це не окремий сайт і не
демо-оболонка: він пакує той самий інтерфейс, локальні PNG-ресурси, аудіо та
правила клієнта, що й вебверсія. Дані гри залишаються в одному Cloudflare
Worker, тому Steam-профіль, віртуальний інвентар, PC, XP, івенти та результати
спільних режимів не дублюються між телефоном і сайтом.

Перед релізною синхронізацією задай **лише HTTPS origin** вже розгорнутого
Worker у локальному середовищі CI/розробника:

```powershell
$env:POTUZHNO_MOBILE_API_ORIGIN = 'https://your-production-worker.example'
npm run mobile:sync
```

Android Steam-вхід працює через системний браузер, одноразовий квиток і
короткоживучий перевірений мобільний токен; браузерні cookie або секрети не
потрапляють у застосунок. Перед публікацією все одно потрібні Android SDK,
підписаний AAB, політика приватності, Data Safety і видалення акаунта в грі та
на вебсторінці. Деталі — у `mobile/README.md`.

## Перед великим запуском

Для production обов’язково створи секрети **в Cloudflare**, а не у файлах репозиторію:

```bash
npx wrangler secret put FAIR_SEED_SECRET
npx wrangler secret put STEAM_WEB_API_KEY
npx wrangler secret put ADMIN_OWNER_PASSWORD
```

Головний вхід не залежить від Google: Steam OpenID підтверджує Steam ID, а
Worker зберігає прогрес саме за цим ID. Той самий Steam на сайті та в Android
автоматично відкриває той самий баланс, XP і віртуальний інвентар. Не потрібно
створювати OAuth Client ID, налаштовувати Google Cloud або зберігати Client
Secret.

- `FAIR_SEED_SECRET` — випадковий рядок від 32 символів. Він дозволяє безпечно обчислювати однаковий щоденний seed у багатьох Worker-шардах і не робити один сервер точкою затору. Встановлюй його перед новою UTC-добою, щоб не змішувати старі й нові proof одного дня.
- `STEAM_WEB_API_KEY` — серверний ключ Steam Web API. З ним Worker бере нік і аватар через офіційний `GetPlayerSummaries`; ключ ніколи не надсилається у браузер. Без нього залишається безпечний запасний режим через публічний профіль Steam.
- `ADMIN_OWNER_PASSWORD` — окремий пароль власника для адмін-панелі, щонайменше 24 символи. Він перевіряється тільки Worker'ом і ніколи не надсилається назад у браузер або GitHub. Згенеруй його в менеджері паролів; не використовуй пароль від пошти чи Cloudflare.

## Адмін-панель і ролі

Панель відкривається за адресою `/admin`. Її API живе окремо від ігрового API, а ролі, сесії та аудит зберігаються у серверному Durable Object. Браузер не може сам призначити собі роль: кожну дію ще раз перевіряє Worker.

- **Власник** — входить через `ADMIN_OWNER_PASSWORD`; захищений від будь-якої зміни в панелі.
- **Повний адмін** — може керувати всіма нижчими ролями, але не власником і не іншими повними адмінами. Також має повне керування віртуальними серверними профілями.
- **Адмін** — може додавати й змінювати модераторів та підтримку; у грі може лише видавати віртуальні нагороди, без скидання чи вилучення даних.
- **Модератор** і **підтримка** — не можуть видавати доступи.

Після входу власник створює учасника, обирає роль і отримує разове посилання. Воно діє 24 години, після першої активації зникає з сервера, а доступ зберігається в `HttpOnly`, `Secure`, `SameSite=Strict` cookie на 14 днів. Призупинення або видалення учасника одразу відкликає всі його активні сесії. Cloudflare Zero Trust, платіжна картка й сторонній логін для цього варіанта не потрібні.

Розділ **«Керування профілем»** відкриває Steam-акаунти прямо зі списку гравців. Адмін не просить у гравця пароль чи код: сервер сам індексує підтверджений Steam ID після першого входу. Там можна видати або встановити віртуальні PC, XP, квитки, Battle Pass, престиж і скіни з серверного каталогу; повний адмін також бачить та може прибрати скіни. Зміна збільшує серверну версію профілю, тому застаріла вкладка не перетирає її, а активна вкладка на тому ж сайті одразу отримує оновлення. Старі Cloud Profile лишаються доступними лише для безпечної міграції. Усі дії потрапляють до журналу.

### 🎲 Перевірювані кейси

- Для кожного відкриття сервер створює HMAC-SHA-256 результат із приватного денного seed, власного client seed, ID пристрою, nonce та ID кейсу.

- Повторний запит із тим самим nonce та параметрами повертає той самий результат; спроба використати nonce для іншого раунду відхиляється. У production недоступний серверний рол скасовує відкриття та повертає баланс. Лише локальна розробка може використати явно неперевірюваний fallback.
- Усе це перевіряє лише віртуальні дропи і PC-значення гри; реальних скінів, грошей або виведення тут немає.

Був неприємний баг: коли гравець перемагав у Royale, його власний предмет **усе одно видалявся** з інвентарю. Тепер логіка правильна:

- 🏆 **Перемога** — свій предмет **залишається** + забираєш 3 предмети ботів
- 💀 **Програш** — свій предмет **видаляється** (переходить переможцю)

## Що вміє гра

- ⚡ **Апгрейд** — три режими входу (скін / мульти / кредити), два режими ролу (понад / під)
- 📦 **Кейси** — 14 тематичних кейсів із відкритими шансами, анімована reel-стрічка й безкоштовний кейс раз на добу
- ⚔️ **Бій 1v1** — 3D-монетка CS вирішує, кому дістанеться предмет суперника
- 👑 **Battle Royale** — 4 гравці, плей-оф на монетках, переможець забирає все
- 📜 **Контракт** — 5 предметів → 1 випадковий
- 🎯 **Завдання** — щоденні, щотижневі, 23 досягнення, 3 колекції з ексклюзивними нагородами
- 💼 **Інвентар** — продаж за 90% вартості, фільтри, сортування, пошук
- 🎨 **Знос** — FN / MW / FT / WW / BS із різними множниками ціни

## Важливо

Не додавайте депозитів, платного ігрового балансу, приймання скинів, трейд-ботів або посилань на переказ коштів заради шансів. Добровільна підтримка може бути лише окремою від гри й не може змінювати баланс, предмети або ймовірності.
